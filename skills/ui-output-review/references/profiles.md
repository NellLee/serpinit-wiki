# UI Output Review Profiles

Use only the profile sections relevant to the current surface.
These profile notes extend the base workflow in `../SKILL.md`; they do not replace it.

## `general`

Use for most complex website surfaces.

Check additionally for:
- whether primary and secondary emphasis are clearly separated
- whether the current state is discoverable without hunting for subtle cues
- whether the relationship between controls and visible result is obvious

## `runes`

Use for `/dev/runes` and other runic visualizations.

Check additionally for:
- whether important runic forms are visually distinguishable from one another
- whether paths, grouping, and ordering suggest readable structural logic
- whether the surface stays honest about showing a reduced projection rather than a total structure

## `content-page`

Use for article-like or lore-heavy pages.

Check additionally for:
- whether reading flow is interrupted by weak spacing or competing blocks
- whether supporting elements reinforce rather than drown the main text
- whether headings and callouts reflect actual content priority

## `search`

Use for search pages and result-driven browsing surfaces.

Check additionally for:
- whether query, filters, and results form one understandable loop
- whether empty, loading, and refined states are clearly differentiated
- whether the result list makes ranking and relevance cues legible

## `dev-surface`

Use for internal tools, inspectors, dashboards, and debug views.

Check additionally for:
- whether density still preserves orientation
- whether technical labels help interpretation instead of overwhelming it
- whether the selected state, inspected object, or active panel is unmistakable
